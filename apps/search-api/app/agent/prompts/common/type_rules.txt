【问题类型判定标准（7 类，与参数可答判定共用）】

归并口径（优先级最高，命中先归并再往下判）：
- 导航型（找官网/文档/入口，如「Pydantic 官方文档在哪」）→ factoid
- 观点经验型（征询看法/体验，如「你怎么看微服务架构」「用 Rust 写后端是种什么体验」）→ multi_facet
- 因果解释型（解释成因/机制，如「为什么 Nginx 比 Apache 更抗并发」）→ multi_facet
- 无法归入前 6 类 → other

判定顺序（未命中归并口径时，依次检查，命中即停）：
① comparison 对比型——两个及以上对象按相同维度比较、评估或做选择（含「A 的优缺点/利弊」这类与同类替代方案的隐式对比）。判例：「pgvector 和 Milvus 个人知识库场景怎么选？」→ comparison。
② how_to 操作型——回答是步骤、方法、配置或故障排查。判例：「FastAPI 怎么配置 CORS？」→ how_to；「docker 容器反复重启怎么排查？」→ how_to。
③ temporal 时效型——答案本体是会过期的状态、数值或事件（版本号/价格/比分/新闻/进展），且问题明示或默认期待最新。判例：「LangGraph 最新版本号是多少？」→ temporal；「今天 A 股大盘收盘多少点？」→ temporal。（时效信号也可经 time_range 字段单独表达，与类型判定解耦。）
④ list 列表型——枚举一组同质条目（有哪些/列举/推荐 N 个）。判例：「Rust 有哪些主流 Web 框架？」→ list。
⑤ multi_facet 多面型——一个主题需拼合多个不同信息面（是什么+为什么+怎么用/影响/背景）才能回答。判例：「什么是向量数据库？为什么要用？主流方案有哪些？」→ multi_facet。
⑥ factoid 事实型——单一事实点：一个实体的一个属性（谁/何时/多少/哪个）。判例：「LightGBM 是哪个公司开源的？」→ factoid。
⑦ other——无法归入前 6 类（闲聊、创作、纯计算、与检索无关的请求）。判例：「帮我写一首关于秋天的诗」→ other。

参数可答判定（answerable_from_knowledge）：仅当问题可由模型通用稳定知识可靠回答——定义/原理/公认事实/成熟操作步骤——且不命中下列任一项，才判 true；命中任一项或拿不准，一律 false：
- 时效敏感（最新版本/价格/新闻/当前状态）；
- 小众或长尾细节（具体参数值、冷门库用法、精确数字）；
- 需要多源佐证的对比或评测结论；
- 依赖用户个人上下文（个人记忆/私有资料）。
true 判例：「什么是 REST API」→ true；「FastAPI 怎么定义一个路由」→ true（成熟文档知识）。
false 判例：「LangGraph 最新版有什么新特性」→ false（时效敏感）；「qwen3.5-4b 的上下文窗口多大」→ false（小众精确数值）。

【检索策略判定标准（产出 search_strategy；在类型判定之后进行）】①命中「零事实面」清单任一项、且问题不含任何需外部取证的事实断言 → direct（同时 answerable_from_knowledge=false）：寒暄/社交与助手元问题（问好、道谢、告别、「你是谁」「你能做什么」）；显式创作/改写/润色请求（写诗/文案/邮件/故事/代码/续写/润色）；翻译请求；纯计算/单位换算（数据全部在问题内）；解释或分析题目自带的代码/文本材料；对既有对话的纯致谢/确认。判例：「你好，能做什么？」→ direct（query_type=other）；「帮我写一首关于秋天的诗」→ direct（other）；「把这句话翻译成英文：……」→ direct（other）。②未命中 direct 且参数可答判定为 true（通用稳定知识 + 四排除项全不命中）→ verify（同时 answerable_from_knowledge=true）。判例：「什么是 REST API」→ verify；「FastAPI 怎么定义一个路由」→ verify。③其余一切（含拿不准、时效敏感、小众细节、需多源佐证、依赖个人上下文）→ web（answerable_from_knowledge=false）。纪律：direct 从严——问题含任何外部事实断言需求（人物/事件/数据/版本/价格/最新状态/客观结论）一律不判 direct；拿不准一律 web；verify ⇔ answerable_from_knowledge=true、direct/web 时 answerable_from_knowledge=false（两字段必须一致）。本节仅 fast.rewrite 消费，deep.planner 不产出不消费 search_strategy。
