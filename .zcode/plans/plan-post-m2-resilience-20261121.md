## A 组：出口抖动韧性（运维/热更级；M2 收尾后即可排；v1 四单保留）

> **2026-11-22 终局更新**：慢性 500 真根因=DashScope 400 content-list 形态缺陷（非网络问题，`docs/diag-deep-400-content-list-20261122.md`），已根治（`_get_request_payload` 出站收敛）+ A③ 钩子落地。**A① 经用户裁决撤销**（触发源消除）；A③ 已闭环；④ 已执行（结论见 diag 文档——排查清单保留为网络故障排查参考）。

### A① LLM 重试窗加宽（**已撤销**——2026-11-22 用户裁决：根治消除触发源，纯网络抖动兜底价值有限且 fast P50 口径敏感；本节留档不再执行）
- 现状：P1a 五键（键位以 nacos-config.md 现行为准）——deep 轮 5 次退避 ~6.4s 全灭于 ≥7s 抖动窗（D3-01 research-1 实测，失败 GENERATION 间隔 0.5~2.7s）。
- 改：deep 轮连接类退避窗拉到 ~20s（次数/间隔上限热更前探针钉）；**fast 轮保持克制**（P50 ≤30s 口径红线，不动或微调后复测）。
- 步骤：读 nacos-config.md 现行键位 → defaults+运行值双沉淀（沿 600s 沉淀先例）→ 单键热更（沿 hotswap 四步脚本，禁 FORCE）→ deep 冒烟一轮。
- 验收：人为 ~8s 出口抖动下 deep 单轮不产子代理失败占位。

### A② 云断落本地 Ollama 兜底（探针先行，裁决后实施；建议 T1~T2）
- 目标：云链（chat-standard/chat-speed）全灭时是否落宿主 `qwen3.5-4b`（=降级梯子 L9）。
- 前置探针：deep 轮 4B 质量代差（工具调用成功率/报告可用性/长上下文容量）+ fast direct/recall 短轮代差 + Ollama 并发容量。
- 预判：deep 不收（4B 工具调用弱、报告代差大）；fast direct/recall 短轮可能收。
- 实施（若裁决收）：litellm fallbacks 链尾加 ollama 腿（config.yaml，git+restart）或应用层降级路由；契约 nacos-config/ARCH 同步。

### A③ 网关 failure 告警钩子（**已闭环** 2026-11-22：GatewayFailureAlerter 落地 `[gateway-failure-alert]`+脱敏三道+76 单测+restart 双活体；评审 pass——本次慢性 500 破案的关键取证工具；原任务书保留在下方）
- 现状：fallback 链耗尽 → 客户端只见 `500 '__aiter__'`，真实原因被掩盖。
- 改：`litellm_callbacks.py` 增 failure 侧钩子——判定「fallback 链耗尽/全部上游不可达」时输出结构化告警行（含原因分类），可 grep、可作出口健康指标（兼做 B 组 L2 探针判定的信号源）。
- 边界：只加观测不改失败语义；与 glm_thinking_guard/OTel 垫片同文件同纪律（异常不外抛）；R8/R16 升级复检同型。
- 验收：人为断外网 5s 触发一次全灭 → 日志出现可读告警行。

### A④ 出口稳定性排查清单（**已执行** 2026-11-22：宿主直连/容器代理链并发全健康→黑盒触顶；结论=故障非出口层，真根因见 diag 文档；清单保留为日后网络故障排查参考）
1. **分层定位**：容器内直连上游（`docker exec ai-search-litellm-1 curl -m 3 -s -o /dev/null -w '%{http_code} %{time_total}' <上游健康端点>`）vs 宿主同命令——隔离「容器 NAT 层 vs TUN 层」。
2. **TUN/代理**：核对系统代理 bypass 名单；TUN/代理掉线日志时间窗与抖动波分钟清单对齐（抖动分钟从 litellm 日志 `Exception occured - 'NoneType'` 聚合提取）。
3. **Docker Desktop 网络栈**：版本更新记录；网络栈重置后观察；compose restart litellm 前后对比。
4. **DNS**：容器内解析时延与偶发失败（容器内 dig 上游域名）——解析抖动与连接抖动同症状。
5. **观测闭环**：A③落地后告警分钟率即出口健康指标（可选 M4 线上评估器规则盯该信号）。

## B 组：断网分级降级（功能级——先立项设计再实施；建议 M2 收尾后立项、M3 前后实施）

**立项形态**：T2——architect 产出 **ADR-017（断网降级路由）**：探针点选型（主动短超时探针 vs 首败被动触发——注意探针不能成为每轮常态延迟税）+ 降级边位置（fast 子图 search 聚集段前；deep 以工具失败占位+降级注记为主，已有雏形）+ state/契约字段 + 梯子路由（L3 直答 → L4 KB → L5 快照 → L6 反问）+ PRD 增量（REQ-0xx 断网降级 + 验收 GWT：标注面/红线/梯子序）+ 契约增量清单（api.md §2.12/§7.4 字段、frontend-api 引导面、`api.d.ts` 镜像）→ 用户批 → 分批实施。

**实施批次建议**：
- **B-1 批**：L2 状态字段+探针+降级边 + L3 非实时直答注记（纯后端+契约，主图拓扑零改动）；
- **B-2 批**：L6 前端反问引导（frontend-api 契约先行）；
- **L4**：归 M3 里程碑本体（M3 落地后降级路由接 KB 一行）；
- **L5**：快照复用检索层（M3 后或与 B-2 并行，契约面=快照复用查询）；
- **L7/L8**：归 M4（沙箱工具 + 红线评测集）。

**与既有决策的关系**：不新增向量栈/不引新组件（M3 裁决为准）；direct/recall/query_type 是 L3 的判定骨架；快照链是 L5 的存储底座；degraded/errors[]/零源分流是 L2 的状态底座；ADR-012 子图内扩展是降级边的拓扑先例。
