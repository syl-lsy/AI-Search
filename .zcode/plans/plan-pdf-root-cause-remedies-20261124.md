# PDF 归一化治本路线立项（四工单）

wf-level: T1 -- 归一化单域（docling_adapter/heading_outline/pdf_textlayer/paddle_engine + 探针），零契约面；实施时逐单 declare

- **立项时间**：2026-11-24，用户裁决「先一一立项吧」（对我方提出的 A/B/C/D 四方向全部批准）
- **背景**：ECMA 标题质量修复轮（Fix 1/2/3+四小修）闭环后自评——确定性信号通道（书签/outlineLvl/字号 bbox/页文本层）为治本；docling 版面模型的误判与漏判本身未消除，现行修复属「兜伤害+纠偏」。用户裁定「结构正确性=硬质量」，本计划将残余治标面逐项转治本。
- **纪律约束**（沿 [[user-structural-quality-hard-gate]]）：确定性信号优先；阈值全部写「相对正文众数比值」（ECMA 每页 0.72 缩放，绝对 pt 不可移植）；每单必须变异敏感性自证；探针自检=验收机器把关，禁逐文件人肉验收。

## 工单 C：探针自检补盲区（小节级校验）——排期第 1（最先）

**问题**：「关于本书」文字级丢失是用户肉眼抓到的、探针自检没抓到的——现行「标题结构自检」节只管书签章级锚点（17/18 校验），小节级漏判/假阳性/误判形态自检不可见。

**目标（治本判据）**：任何 PDF 跑完探针即出**小节级伤情单**，机器先于用户抓到以下五类异常；自检不可见的缺陷类别清零。

**范围**（`scripts/probe_kb_pipeline.py` 自检节 v2，开发工具不进生产链）：
1. **书签召回缺失检测**：书签条目在树内零命中者逐条列出（治「修改记录」类——现行只报命中 17/18，不报缺失的是谁）。
2. **标题密度异常**：heading/千字 与 heading/页 分布；超阈值（Nacos 式可调常量）列嫌疑清单——治「修改为：」×5 假阳性。
3. **提升行形态矩阵**：对 Fix 2 提升的每行输出形态（句末标点/行数/字数/字号比值）——句末正则缺口（P3-1）可量化暴露。
4. **空 text 候选**：text 空且有 orig 的节点计数与标题占比——治 formula 误判类（Fix 1 通道的活跃度监控）。
5. **无书签警示**：correction_path=none 时输出「版面推断主导，层级可信度降级」显著警告（伤情单第一行）。

**验收**：ECMA 标本上 ①~④ 全部命中已知缺陷（修改记录缺失/修改为×5/8 条提升形态/2 条 formula 候选）；docx 标本+sample_structured 零误报；关闭态零变化。
**依赖**：无。**风险**：低（纯观察工具）。**实施级**：T1。

## 工单 B：docling 输出多信号复核层——排期第 2

**问题**：docling 版面模型三类误判未被消除（Fix 1 只兜伤害）：①正文短语判标题（假阳性「修改为：」×5）；②标题误判 formula（「关于本书」类，无书签时无救）；③标题误判 code/其他类型未审计。

**目标（治本判据）**：docling 输出的每个类型标签在进 IR 前过**排版事实复核门**——标签与排版信号矛盾者纠正，而非事后补救。误判在源头被消除，不再依赖「有书签才能救」。

**范围**（`app/rag/normalizers/docling_adapter.py` + 新复核模块，全部走关闭态开关+护栏）：
1. **section_header 门**：非书签锚点 heading 必须满足（字号 ≥ 正文众数×比值阈值 **或** 加粗〔GetFontWeight≥700〕**或** 独立短行+上下留白），不满足者降级回正文段。只降级不升级（升级仍归 Fix 2 提升通道）。
2. **formula 复核**：formula 候选 bbox 内字号=正文众数且行宽近满行 → 降级为文本段（走 orig/提升通道）——「关于本书」类在**无书签场景**也能归位。
3. **code 复核**：code 候选核字体名信号（`FPDFText_GetFontName` 等宽字体命中；等宽缺失且字号=正文众数者降级）。
4. **负例用例锁**：真标题不被误降（加粗同字号标题、代码块、真公式三负例）+ 变异敏感性自证。

**验收**：ECMA「修改为：」×5 降级回正文段；关闭书签校正（KB_PDF_OUTLINE_CORRECTION=false）后「关于本书」仍归位；真标题/真代码/真公式零误降；零丢字回归；docx/sample_structured 逐字节回归。
**依赖**：工单 C（自检先行才能量化复核效果）；P3 挂账句末正则/负例用例随本单清偿。
**风险**：降级过猛伤真标题——阈值全部相对比值+负例锁死+关闭态回退门。**实施级**：T1。

## 工单 A：书签升格骨架源——排期第 3（宜随 B18/B20 写入通道前）

**问题**：现行书签校正只「钉层」不「造节点」——「修改记录」书签里有、树里没有，召回缺失无解；无锚点小节的层级仍靠版面推断。治本形态=有书签的 PDF 以书签为骨架重建标题结构。

**目标（治本判据）**：有书签且护栏通过的 PDF，树内 heading 结构与书签大纲**同构**（书签有的树里有，层级一致）；书签缺失/护栏拦截时回落现行路径等价。

**范围**（`heading_outline.py` 扩展 + `docling_adapter.py` 装配序）：
1. **骨架重建模式**：书签条目→IR heading 节点；内容归属按相邻书签页码区间+文本边界界定；书签有而版面识别无的条目**造节点**（空标题节点允许，正文直接归属）。
2. **无锚点 heading 存废判据**：树内已有、书签没有的 heading，按工单 B 复核门定存废（过门保留挂最近锚点下，不过门降级）。
3. **旧裁决修订落档**：T1-b「校正不造节点」裁决由本单推翻（用户 2026-11-24 立项批准即授权），交付说明留修订记录。
4. **护栏沿用**：双层护栏（整体≥0.6 或顶级≥0.6 且≥3）不通过=不启用骨架重建，回落现行路径。

**验收**：ECMA「修改记录」归来（L1，其下内容归属正确）；17/18 锚点零偏差不回退；重复章名消歧不劣化；无书签标本（sample_structured）回落逐字节等价；零丢字。
**依赖**：工单 B（复核门=无锚点 heading 的存废判据）。**契约面**：零（IR schema/REST 不变，heading 数量语义变化在探针自检与交付口径更新）。
**风险**：内容归属边界（页码区间切分）是设计难点——书签只给标题+页码；变异矩阵+伤情单双验证。**实施级**：T1。

## 工单 D：OCR 质量闭环（升级链落地）——随 B21 实施，本单先行范围钉定

**问题**：OCR 管线（触发/插入/去重）已治本，但**识别质量**对疑难件（模糊/盖章/倾斜/手写）无闭环——PaddleOCR 输出差就是差，无兜底。

**目标（治本判据）**：OCR 质量有确定性度量与升级链兜底（用户既有裁决：质量判据=确定性信号优先〔文字产出量/置信度/版面密度阈值走 Nacos 热更键〕，模型自评留灰度备选）。

**范围**（归 B21 契约增量批+实施，与处理矩阵四行同批）：
1. 质量度量键：`kb.ocr.quality.*`（产出量/置信度阈值，Nacos 热更）。
2. 升级链：文字类 OCR 质量差 → GLM 描述升格为主内容（处理矩阵①的兜底半边，非默认）。
3. 扫描页页级 VLM 粒度键：无文本层页/含图页/全量，灰度可调（处理矩阵④）。

**验收**：随 B21 验收单（合成疑难件 + 真扫描标本对照）。
**依赖**：B21 立项（契约增量批先行：data-model 父子引用+nacos kb.image.*/kb.ocr.quality.* 子节+ARCH ADR-018 增注）。
**实施级**：随 B21（T2 契约批+T1 实施）。
