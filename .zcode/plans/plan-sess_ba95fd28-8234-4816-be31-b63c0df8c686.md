## 凭据纪律

- **AI 生成的容器侧密钥**（openssl rand，写 `.env` 不回显、不进上下文、不进对外产物）：Nacos 鉴权四件套值、`LITELLM_MASTER_KEY`/`LITELLM_SALT_KEY`/`LITELLM_UI_PASSWORD`/`LITELLM_DB_PASSWORD`、`LANGFUSE_SALT`/`LANGFUSE_ENCRYPTION_KEY`/`LANGFUSE_NEXTAUTH_SECRET`、`CLICKHOUSE_PASSWORD`、`MINIO_ROOT_USER/PASSWORD`、`OPEN_SANDBOX_API_KEY`、**`CRAWL4AI_API_TOKEN`（自部署服务的自设口令，无厂商申请环节，`openssl rand -hex 32` 生成，compose 注入容器开 Bearer 鉴权）**。

## 关键风险与坑（实施对照）

1. healthcheck 需自补（nacos/litellm/langfuse-web/worker 无现成模板），否则「全 healthy」判据不成立。
2. Langfuse S3 桶名错配 = 静默 403；Langfuse 容器端口 3030 vs 3000 实施核实。
3. Nacos v3 控制台 8080 无 `/nacos` 路径；namespace 名=ID 必须显式同值；403 实证必须用临时 probe dataId 且测毕删除。
4. MinIO chainguard 仅 latest 可用 → 锁 digest 留档；凭据形态以镜像实际为准。
5. LiteLLM config.yaml = 官方标准 schema + 契约冻结键位（别名/fallback/熔断只写此文件）；改它需重启容器，非热更通道；上游 model id 用 `os.environ/` 引用。
6. OpenSandbox 必须挂 docker.sock + `host.docker.internal:host-gateway`。
7. 上游密钥空占位不阻塞起栈（`${VAR:-}`），litellm 起来但模型调用报错——smoke 留 B 组，不误判为部署失败。
8. `LANGSMITH_TRACING=false` 必须显式落 .env，防止 LangChain 默认行为把 trace 上报 LangSmith 云（与观测走 Langfuse 的契约口径冲突）。
