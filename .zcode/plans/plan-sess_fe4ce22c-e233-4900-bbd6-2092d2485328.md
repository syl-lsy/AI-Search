## Context

目标：打通「LangGraph Studio（开发期图观测）+ 自托管 Langfuse（trace 跟踪）」双工具面。两者机制正交：LangSmith 走 env 变量驱动、Langfuse 走显式 CallbackHandler（`turn_service.py:1210` 已实证），可共存；`LANGSMITH_TRACING` 维持既有裁决固定 false（trace 不出本机）。

探索发现的两个真问题（本次要修）：
1. **`apps/search-api/langgraph.json` 用文件路径入口**（`./app/agent/graphs/main.py:graph`）——langgraph_api 以 `spec_from_file_location + exec_module` 绕过 `sys.modules` 加载，启动期 **5 次重复编译**（main 1 + fast 2 + deep 2），违反 `registry.py:12-14`「import 即编译一次、进程内单例复用」不变量，Studio 暴露的图与 `GRAPH_REGISTRY` 不是同一实例。
2. **DEV §5.3 现行命令 `cd apps/search-api && langgraph dev` 读不到仓库根 .env**（`config.py:38` env_file 相对 cwd 解析）——settings 全回落默认值，与「命令一律从仓库根跑」铁律冲突。

## 改动清单

### 1. langgraph.json 入口改模块路径（修编译不变量）
`apps/search-api/langgraph.json` 三条 entries 改为：
```json
"main": "app.agent.graphs.main:graph",
"fast": "app.agent.graphs.fast:graph",
"deep": "app.agent.graphs.deep:graph"
```
效果：langgraph_api 走 `importlib.import_module` 命中 `sys.modules`，三图各编译一次，Studio 暴露的 `graph` 与 `GRAPH_REGISTRY` 条目同实例。不新建 adapter 文件（`module:variable` 已够，多一个入口反而多一个编译源）。

- 同一性断言：`registry.GRAPH_REGISTRY["fast"] is fast.graph`、deep 同理（防未来重构引入双编译回归）。
